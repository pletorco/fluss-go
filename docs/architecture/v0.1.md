# fluss-go public architecture v0.1

Status: implemented and verified for the initial 0.9.1 client.

See also [request coalescing](request-coalescing.md) for shared-operation
context, cancellation, result ownership, and the build-vs-buy decision.

This document fixes the initial architecture for Apache Fluss
0.9.1-incubating, resolved to commit
6bf969f71af8d6f9cc37383ab89ae46a58b0e227. Later Apache Fluss APIs are out
of scope until a separately reviewed compatibility update.

## Package boundaries

    pkg/fadm --> pkg/fgo --> internal/transport --> pkg/fmsg
        |           |
        +-----------+---------------------------> pkg/fmsg

- fmsg owns API keys, versions, generated requests and responses, protocol
  errors, and wire codec contracts. It imports neither public client package
  nor any transport package.
- fgo owns the shared client, authentication, negotiated connections, metadata
  refresh and routing, data-plane APIs, rows, schemas, offsets, and Arrow
  adapters. It imports fmsg and internal/transport.
- fadm owns administrative APIs and immutable administrative result types. It
  is constructed from an fgo client and reuses that client's negotiated
  connections, metadata, and lifecycle. It imports fgo and fmsg.
- internal/transport owns bounded framing, request correlation, cancellation,
  and connection shutdown. It imports fmsg and is never a public API.

The dependency direction is acyclic. fmsg does not import either public client
package, fgo does not import fadm, and internal/transport does not import a
public client package.

## Client and raw requests

fgo.Client is opened from options. fadm.New accepts an existing fgo.Client so
administrative and data operations share one connection manager. The common
raw escape hatch is deliberately narrow:

    type Requester interface {
        Request(context.Context, fmsg.Request) (fmsg.Response, error)
    }

fgo.Client provides Requester() fmsg.Requester and routed coordinator, node,
and bucket request methods. All paths retain authentication, version
validation, request correlation, metadata routing, and error classification.
fadm does not expose or own a second transport.

## Lifecycle and concurrency

Clients are safe for concurrent use. Close is idempotent, unblocks pending
requests with an error, and prevents new requests. Calls after Close return
ErrClosed.

Tables are immutable handles and are safe for concurrent use. Writers,
scanners, and lookupers are independently closeable resources. Their
methods are not concurrently safe unless documented otherwise; the parent
client may still be used concurrently.

Every blocking operation accepts context.Context. A canceled context stops
waiting and returns its context error where that is the causal error. Client
close takes precedence when it has already invalidated the operation.

Writer.Flush(ctx) waits until all writes accepted before the call have a
terminal result. It never silently discards failures. Writer.Close(ctx)
flushes accepted writes, releases resources, and is idempotent after a
successful close.

Async writes return a result handle. Calling Await(ctx) returns exactly one
terminal result: success with a stable record result, a classified server or
transport error, or the caller context error. A result is never changed after
it becomes terminal.

Log scanners provide explicit Poll(ctx) polling. It returns a ScanResult when
records are available and context or classified transport errors otherwise.
An unbounded scanner waits until a record, cancellation, close, or terminal
transport failure; it does not use hidden background retry loops. Row limits,
exclusive stopping offsets, and Wakeup provide bounded completion and explicit
poll interruption without changing the scanner's ownership rules.

Batch scanners are bound to one resolved table bucket. A current-state scanner
performs one LIMIT_SCAN request, while a snapshot scanner delegates immutable
snapshot storage to a configured SnapshotBatchProvider. Poll calls are
serialized, Close cancels an active poll, and BatchResult owns any Arrow
batches it returns until Release is called.

## Rows, schemas, and Arrow

fgo.Row is the portable, schema-aware value API. It exposes validated
field/value access and never exposes wire structs. Arrow support is an optional
data-plane adapter built around Apache Arrow Go record batches. It uses explicit
ownership: callers retain an AppendArrow input batch until the returned
WriteFuture completes. Callers must release decoded or scanned Arrow batches
according to the Arrow Go contract.

Row and Arrow APIs coexist at the fgo boundary and share only internal
encoding/decoding code. fmsg remains free of Arrow and table-model types.

Typed clients are wrappers around these row-oriented resources. They use
explicit Codec and KeyCodec implementations and inherit the wrapped resource's
ordering, cancellation, error, and ownership behavior. Codec failures are
returned directly; they do not trigger fallback conversion.

## Observability and filesystem tokens

MetricsObserver receives bounded-cardinality events for RPC, retry, remote I/O,
write, scan, decode, and throttle operations. Events exclude addresses, table
paths, bucket IDs, request payloads, credentials, token bytes, and server error
messages. Observer panics are isolated from client operations. The optional
OpenTelemetry API adapter and application-owned exporter lifecycle are
documented in [observability](../observability.md).

Filesystem security tokens are managed by one client-owned refresh loop when
enabled. The default provider requests tokens through the negotiated
coordinator connection; an application may supply another provider and
receivers. Tokens are cloned at publication and consumption boundaries,
redacted when formatted, and not returned after revocation or expiry. Closing
the client stops refresh without waiting for a reentrant or blocked receiver;
the last cached token remains readable only while it is still valid. Remote
storage remains pluggable and does not add a mandatory filesystem SDK
dependency.

## Errors and compatibility

Public errors support errors.Is and errors.As. Sentinel errors classify local
state and validation failures (ErrClosed, ErrInvalidArgument, and
ErrUnsupportedVersion); typed errors preserve server error codes, API key,
endpoint, and retryability without leaking credentials or raw frames.

Before v1, exported APIs may evolve only through reviewed, documented changes.
Removing or behaviorally changing an exported symbol requires a deprecation
period unless it corrects a security or correctness defect. Generated fmsg
types follow the pinned Fluss protocol exactly and are regenerated rather than
hand-edited.

Compatibility means interoperability with the pinned Fluss 0.9.1-incubating
protocol. It does not promise compatibility with future server protocol
versions until their ranges and behavior are explicitly added.
