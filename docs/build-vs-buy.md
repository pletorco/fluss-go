# Build-vs-buy decisions

This register records reviewed exceptions and dependency choices under the
project build-vs-buy rule. It is not a blanket approval for similar future
code. A decision must be revisited when its requirements, available libraries,
supported Fluss version, maintenance state, license, or security assumptions
change.

| Area and owner | Classification and decision | Alternatives and dependency impact | License and security | Compatibility and evidence |
| --- | --- | --- | --- | --- |
| Fluss wire codecs (`pkg/fgo`) | Justified internal implementation of Fluss row, key, KV, and log framing; reuse `encoding/binary`, `hash/crc32`, generated protobuf, and Arrow-Go primitives. | General serializers do not implement compacted/indexed Fluss 0.9.1 layouts or record headers. Copying Java internals would enlarge the derived-code surface. Arrow IPC and its compression support are reused. | Standard library code has no supply-chain cost. Arrow-Go is Apache-2.0/BSD-3-Clause and remains security-gated; malformed sizes and allocations are bounded. | Java byte fixtures, round trips, malformed-input tests, fuzz targets, and live integration pin wire compatibility to Fluss 0.9.1. |
| Fluss bucket hashing (`pkg/fgo`) | Justified, isolated Java-compatible adapter over small hash primitives. | Generic Murmur3 packages provide the primitive but not Fluss's seed-42 byte hash, signed tail expansion, second integer hash, and Java absolute-value edge case. A dependency would still leave the compatibility composition local. | No cryptography is claimed. The implementation has no module dependency or unbounded input and is not exported as a general hash. | [`bucket.go`](../pkg/fgo/bucket.go) is checked against pinned Java 0.9.1 fixtures. |
| SASL PLAIN and TLS (`pkg/fgo`) | Justified minimal RFC 4616 state adapter; mandatory reuse of `crypto/tls` for all TLS and certificate behavior. | Broad SASL frameworks add mechanisms and transitive surface unused by Fluss 0.9.1. New mechanisms require a fresh maintained-library evaluation; TLS or cryptography may never be reimplemented here. | Standard library licensing applies. Credentials are validated, temporary responses are cleared, and secret values are excluded from errors and metrics. | State, challenge rejection, buffer clearing, and credential tests plus the pinned SASL integration cluster provide evidence. |
| Protocol generation (`cmd/protocolgen`, `pkg/fmsg`) | Mandatory reuse of official `protoc` and `protoc-gen-go`; justified small registry generator for pinned Java enums. | `FlussApi.proto` has a standard compiler path. `ApiKeys.java` and `Errors.java` are not code-generation schemas, so the local parser extracts only the public registry rather than copying generated Java code. | Protobuf uses BSD-3-Clause. Pinned upstream source hashes, NOTICE data, tool versions, and Trivy/govulncheck constrain provenance and updates. | Entry counts, generated formatting, protocol tests, and `task verify:generate` verify deterministic Fluss 0.9.1 output. |
| Framed transport and correlation (`internal/transport`) | Justified Fluss-specific orchestration over `net`, `io`, contexts, and generated protobuf messages. | General RPC transports do not provide Fluss's length framing, API/version header, correlation IDs, cancel-with-late-response handling, or connection replacement semantics. Replacing TCP/TLS primitives is prohibited. | Standard library network and synchronization primitives add no dependency. Frame lengths, correlation state, shutdown, and sensitive errors are bounded or validated. | Fragmented frames, malformed lengths, cancellation races, exactly-once completion, fuzzing, race tests, and live requests cover the boundary. |
| Duplicate request coalescing (`pkg/fgo`) | Justified small reusable helper owned only by client metadata/schema paths. | `golang.org/x/sync/singleflight` lacks independent waiter cancellation, last-waiter operation cancellation, close errors, and disposal of unclaimed owned resources. Wrapping it retains nearly all required state and adds a module. | Standard concurrency primitives only; no new license or vulnerability surface. Results are disposed explicitly and cancellation cannot leak resources. | Owner/waiter/all-cancel, replacement, close races, result sharing, and disposal tests are documented in [request coalescing](architecture/request-coalescing.md). |
| Schema resolution and cache (`pkg/fgo`) | Justified client-owned, 256-entry LRU plus the reviewed coalescer. | `container/list` supplies LRU mechanics. Generic cache modules do not combine Fluss schema-ID validation, independent cancellation, owned-schema disposal, client close, and target-schema projection; adding one would not remove protocol logic. | Standard library only. Capacity is fixed, malformed schemas fail closed, and no schema or table identifiers enter metrics. | Concurrent miss, eviction, cancellation, malformed response, mixed historical schema, race, and live evolution tests are described in [schema evolution](schema-evolution.md). |
| Retry and backoff policy (`pkg/fgo`) | Justified bounded policy using `context` and `time`; mutation retries are opt-in and sequence-aware. | Generic retry libraries do not know negotiated API safety, connection replacement, duplicate Fluss writer sequences, byte-identical replay, lookup mutation exclusion, or bucket poisoning. They would wrap rather than replace the state machine. | Standard library only. Attempt counts and delays are validated; cancellation stops waits; unsafe mutations are never silently replayed. | Timeout, cancellation, terminal and temporary errors, duplicate sequence recovery, exact byte/sequence preservation, race tests, and live failover provide evidence. |
| Writer scheduling (`pkg/fgo`) | Justified writer-local bounded queue, dynamic fill under fixed caps, and one in-flight request per bucket. | A generic worker pool cannot preserve per-bucket order, writer IDs, sequence recovery, flush barriers, independent writer failure, and caller ownership. Shared schedulers, same-bucket concurrency, adaptive caps, and allocators were benchmarked and rejected for the current release. | Standard library only. Record and request bounds constrain memory; close and failures have deterministic ownership. | Saturation, ordering, ambiguous failures, shutdown, race tests, and comparative benchmarks are recorded in [write scheduling](write-scheduling.md). |
| Cross-call lookup scheduling (`pkg/fgo`) | Justified client-local scheduler using Go concurrency primitives. | Generic batching/retry packages do not jointly model Fluss bucket/mode compatibility, independent cancellation, ordered partial results, mutation-aware retry exclusion, and deterministic close. Composition leaves the scheduler state local and adds dependencies. | Standard library only. Queue, delay, key count, workers, timeout, and attempts are bounded; mutation retries are prohibited. | Saturation, cancellation, close, retry, race, and comparative benchmarks are covered in [lookup scheduling](lookup-scheduling.md). |
| Remote range prefetch (`pkg/fgo`) | Justified storage-neutral scheduler around `io.Reader`, `io.ReaderAt`, and contexts. | Cloud and HDFS protocols remain delegated to official SDKs. Generic downloaders cannot enforce Fluss segment ordering, gap/overlap checks, token cloning, snapshot association, and this client's metric/retry contract without equivalent orchestration. | Standard library only in core. Object, total, active-stream, and active-byte limits prevent unbounded allocation; paths and credentials stay out of metrics. | Out-of-order completion, exact ranges, cancellation cleanup, legacy adaptation, race tests, and slow-object benchmarks are covered in [remote storage](remote-storage.md). |
| Filesystem security-token lifecycle (`pkg/fgo`) | Justified Fluss-specific refresh coordinator; token acquisition remains on negotiated Fluss RPCs and storage authentication belongs to adapters. | Generic credential caches do not model Fluss filesystem identity, server expiry, refresh skew, cloned token ownership, shared reader use, and client shutdown. Cloud/HDFS signing or authentication must use official SDKs. | Standard library synchronization only. Secret bytes are cloned, cleared on replacement/close, never logged or measured, and refresh loops are bounded to one per client. | Expiry, refresh, cancellation, replacement, zeroization, concurrent reader, and shutdown tests plus live token RPCs protect the lifecycle. |
| Amazon S3 transport (`adapters/s3`) | Mandatory reuse of official AWS SDK for Go v2 behind an optional thin adapter. | Implementing SigV4, endpoint rules, ranged GET, checksums, credentials, or SDK retry behavior locally is prohibited. The adapter maps exact Fluss ranges and validates returned metadata. HDFS and OSS require separate reviews. | Initial S3 pin v1.106.2; AWS modules are Apache-2.0. The optional boundary keeps the SDK out of core; govulncheck, Trivy, Dependabot, range bounds, body close, and error identity are gated. | URI/range mapping, metadata mismatch, ownership, cancellation, allocation, and opt-in service tests are documented in the [S3 adapter manual](../adapters/s3/README.md). |
| Alibaba Cloud OSS transport (`adapters/oss`) | Mandatory reuse of the official Alibaba Cloud OSS SDK for Go v2 behind an optional thin adapter. | Implementing V4 signing, endpoint rules, credentials, ranged GET, or SDK retry behavior locally is prohibited. Shared protocol-neutral URI and range validation is reused with the S3 adapter. | Initial OSS SDK pin v1.5.3; the module is Apache-2.0 and was released 2026-07-17. The optional boundary keeps it out of core; govulncheck, Trivy, Dependabot, exact metadata validation, body close, and error identity are gated. | URI/range mapping, standard range behavior, mismatch cleanup, cancellation, examples, and the opt-in service test are documented in the [OSS adapter manual](../adapters/oss/README.md). |
| Metrics event boundary (`pkg/fgo`) | Justified small backend-neutral synchronous observer contract; no exporter is selected by core. | Standard logging and `expvar` do not provide application-selected metrics backends. Importing an observability SDK into core would force lifecycle, cardinality, and dependency policy on all users. | Core uses no metrics dependency. Events contain bounded enums, counts, and durations only; observer panics are isolated and sensitive identifiers/text are prohibited. | Emission, error classification, panic isolation, cancellation, and operation-specific tests define the contract in [observability](observability.md). |
| OpenTelemetry metrics (`adapters/otel`) | Mandatory reuse of the official stable OpenTelemetry Go metrics API in an optional adapter. | Reimplementing a metrics SDK, aggregation, export protocol, or Prometheus/OTLP client is prohibited. Applications select and own the SDK, reader, exporter, flush, and shutdown lifecycle. | Initial pin v1.44.0, Apache-2.0/BSD-3-Clause. API-only imports keep SDK/exporter I/O and transitive dependencies outside core; security gates inspect the graph. | Mapping, bounded attributes, operation-specific values, panic isolation, concurrency, allocation, and compile examples are documented in [observability](observability.md). |
| Markdown and Task reference validation (`cmd/mdcheck`) | Mandatory reuse of goldmark v1.8.5 and the already-present `yaml.v3` v3.0.1 parser; justified repository-policy checks over their ASTs. | Regex-only Markdown or YAML parsing was rejected. External link checkers add Rust or Node distribution trees and focus on network checks. The local code only resolves repository links, synchronized Go snippets, and `task` references. | Goldmark is MIT; `yaml.v3` is MIT/Apache-2.0. Neither executes document content or performs network I/O. Dependabot, govulncheck, and Trivy own updates; the parser remains tooling-only. | Link, anchor, escape, generated-file, snippet, malformed Taskfile, valid/stale task, write-mode, and command-level tests are described in [documentation validation](documentation-tooling.md). |

## New decisions

A PR that adds a dependency or custom implementation must classify the change
in the pull-request template. It must add or update a row when the decision is
architectural, security-sensitive, protocol-specific, or likely to be reused.
The row names its maintenance owner, alternatives, dependency and license
impact, security boundaries, compatibility target, and reproducible evidence.
Small one-off decisions may remain in the PR description when all evidence
required by `CODING_GUIDELINES.md` is present.
